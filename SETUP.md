# Casario → из прототипа в рабочее приложение

Приложение уже умеет много (гиды, объявления, чат, профиль, кошелёк) и **сохраняет данные локально**.
Чтобы оно стало **настоящим** (общие аккаунты, единая база, живой чат между людьми, платежи) — нужен бэкенд.
Всю интеграцию пишу я. От тебя — 2 коротких шага (их за тебя сделать нельзя: это твои аккаунты и ключи).

## Шаг 1. Бэкенд — Supabase ✅ (сделано)
Проект подключён, ключи вставлены, таблицы созданы (profiles, listings, messages, briefs)
из `supabase/migrations/20260801120000_init.sql`. Проверено — база отвечает.
Осталось (если ещё не сделала): **Storage → New bucket → `media`, публичное чтение** —
для аватаров и фото объявлений.

## Шаг 2. Деплой — сделать сайт «живым» (нужно 1 действие от тебя)

Магический вход по email заработает только когда сайт живёт по настоящему адресу.
Я уже положил в репо автодеплой. Выбери один вариант:

> ⚠️ Твой репозиторий **приватный**. Автодеплой через GitHub Actions я настроил и
> проверил (сборка `index.html` проходит), **но саму публикацию Pages включить
> кодом нельзя** — GitHub не даёт токену workflow права создавать Pages-сайт, плюс
> Pages для приватного репо требует платного плана. Поэтому выбор ниже.

### Вариант A — Netlify (рекомендую для приватного репо) ⭐
Работает с приватным репозиторием бесплатно, свой домен, ничего публиковать не надо.
1. Зайди на https://netlify.com (войти через GitHub).
2. **Add new site → Import an existing project → GitHub → `casario`**.
3. Настройки сборки Netlify возьмёт из `netlify.toml` (уже в репо) — просто **Deploy**.
   - ветку можно указать `claude/correctness-check-0q39av` или `main` (после мержа).
4. Получишь адрес вида `https://<имя>.netlify.app` (позже можно свой домен).
5. В Supabase → **Authentication → URL Configuration** пропиши этот адрес
   в **Site URL** и **Redirect URLs**.

### Вариант B — GitHub Pages (бесплатно, если репо сделать публичным)
1. **Settings → General → Danger Zone → Change visibility → Public**
   (anon-ключ Supabase безопасен в публичном коде — данные защищает RLS; секретов в репо нет).
2. **Settings → Pages → Build and deployment → Source: `GitHub Actions`**.
3. Смёрж ветку в `main` (workflow деплоит с `main`) — через ~1–2 мин сайт будет тут:
   **https://marino4ka-witch.github.io/casario/**
4. В Supabase → **Authentication → URL Configuration** пропиши этот адрес
   в **Site URL** и **Redirect URLs**.

*(Вариант B с приватным репо возможен только на платном GitHub Pro/Team.)*

> Важно: без шага «Redirect URLs» письмо со ссылкой придёт, но по клику Supabase
> не пустит обратно в приложение. Это одна строка в настройках — и вход заработает.

### Письма (email) для входа
Supabase на бесплатном тарифе шлёт письма со своего адреса с лимитом (~3–4/час) —
для теста хватает. Для продакшена подключи свой **SMTP**
(Authentication → Emails → SMTP): подойдёт Resend/Brevo/SendGrid — скажи, помогу настроить.

## Шаг 3. Платежи — Telegram Stars ⭐ + крипта ₿ (код готов)

> 🇷🇺 **Без Stripe/PayPal** — с российским паспортом они недоступны. Деньги идут
> только через **Telegram Stars** (основной способ) и **крипту (USDT TRC20 / BTC)**.
> Кнопка «Картой» оставлена как **«скоро»** — заглушка на будущее, не через западный
> процессинг.

Единый платёжный слой уже в приложении (`window.PAY`):
- **внутри Telegram** (Mini App) → оплата **Stars** нативно (`openInvoice`);
- **на обычном сайте** → кнопка Stars ведёт в бота **@casario_app_bot** (`t.me/casario_app_bot?start=pay_<товар>`), оплата там;
- **крипта** → реквизиты USDT (когда впишешь кошелёк в `CASARIO_CFG.USDT_TRC20`).

Без ключей всё работает как демо и ничего не ломается. Серверная часть — две
Edge Functions в `supabase/functions/`: `create-invoice` (счёт на Stars) и
`tg-webhook` (подтверждение оплаты).

### 3.1 Бот и Stars ⭐
1. Бот уже есть — **@casario_app_bot** (вписан в `CASARIO_CFG.TG_BOT`).
2. Включи боту приём Stars: **@BotFather → бот → Payments → Telegram Stars**.
3. Задай секреты и задеплой обе функции:
   ```bash
   supabase link --project-ref vlhexxuzhdfiklcymawj
   supabase secrets set TELEGRAM_BOT_TOKEN=123456:ABC...   # токен из @BotFather (Copy)
   supabase secrets set STARS_PER_USD=60                   # сколько ⭐ за $1 (подстрой под курс)
   supabase secrets set TG_WEBHOOK_SECRET=$(openssl rand -hex 16)   # запомни это значение
   supabase functions deploy create-invoice --no-verify-jwt
   supabase functions deploy tg-webhook   --no-verify-jwt
   ```
4. Создай таблицу покупок (Supabase → SQL Editor) из
   `supabase/migrations/20260803120000_purchases.sql`.
5. Зарегистрируй вебхук в Telegram (один раз), подставив токен, ref и секрет:
   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://vlhexxuzhdfiklcymawj.functions.supabase.co/tg-webhook&secret_token=<TG_WEBHOOK_SECRET>&allowed_updates=[\"pre_checkout_query\",\"message\"]"
   ```
6. В **@BotFather → Mini Apps** пропиши адрес сайта из Шага 2 —
   приложение откроется внутри Telegram с нативной оплатой Stars.

Что происходит при оплате: клиент зовёт `create-invoice` (с проверкой подписи
`initData`) → получает ссылку → `openInvoice` → Telegram проводит оплату →
`tg-webhook` отвечает на `pre_checkout_query` и записывает покупку в `purchases`.

### 3.2 Крипта ₿ (USDT TRC20 / BTC)
1. Заведи кошелёк (например USDT TRC20).
2. Впиши адрес в `casario-prototype.html` → `window.CASARIO_CFG.USDT_TRC20 = "T..."`.
3. Кнопка «₿ Крипта» покажет пользователю адрес и сумму; подтверждение перевода
   пока ручное (автосверку по блокчейну добавим позже — скажи).

> Пришли мне **токен бота** через секреты (не в чат!) — и я задеплою и проверю
> оплату вживую. Секреты я **не коммичу** в репозиторий.

## Что делаю я (весь код)
- Вход по email (magic link) + анонимный режим для «просто посмотреть».
- Облачные: профиль, объявления (общие, с модерацией), чат по странам (realtime), заявки на подбор.
- Честный **поиск-консьерж**: бриф → в базу → ты/агент с AI присылаешь 10 вариантов.
- Мягкий фолбэк: без ключей всё работает как сейчас (localStorage) — ничего не ломается.
- Платежи (Stars/крипта) и деплой — по выбору из Шага 2.

> Пиши сюда два значения из Шага 1 — и поехали делать по-настоящему.

## Производительность (первый экран)
- Файл — один HTML: **~1.25 МБ на диске**, но по сети хост отдаёт его сжатым:
  **~580 КБ gzip** (Netlify/большинство хостингов включают gzip/brotli автоматически —
  brotli даёт ещё меньше, ~450–480 КБ). Для контентного приложения это нормально.
- Тяжёлые части: фото стран (~500 КБ) и тексты гидов + карта (~750 КБ).
  Фото стран и гиды **рендерятся по требованию** (только когда открываешь страну),
  а не все сразу — первый экран лёгкий.
- Картинки помечены `decoding="async"` / `loading="lazy"`, чтобы не подвешивать прокрутку.
- **Хочешь ещё быстрее на реальном сайте?** Можно вынести фото/гиды в отдельные
  файлы и кешировать их браузером (сейчас всё в одном файле — так работает превью
  в claude.ai, где внешние запросы запрещены). На Netlify это безопасно и ускорит
  повторные заходы — скажи, и я разнесу ассеты для деплой-версии.
