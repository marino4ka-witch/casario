# Casario → из прототипа в рабочее приложение

Приложение уже умеет много (гиды, объявления, чат, профиль, кошелёк) и **сохраняет данные локально**.
Чтобы оно стало **настоящим** (общие аккаунты, единая база, живой чат между людьми, платежи) — нужен бэкенд.
Всю интеграцию пишу я. От тебя — 2 коротких шага (их за тебя сделать нельзя: это твои аккаунты и ключи).

## Шаг 1. Бэкенд — Supabase ✅ (сделано)
Проект подключён, ключи вставлены, таблицы созданы (profiles, listings, messages, briefs)
из `supabase/migrations/20260801120000_init.sql`. Проверено — база отвечает.
Осталось (если ещё не сделала): **Storage → New bucket → `media`, публичное чтение** —
для аватаров и фото объявлений.

## Шаг 2. Деплой — сделать сайт «живым» (нужно 1 действие от тебя)

Магический вход по email заработает только когда сайт живёт по настоящему адресу.
Я уже положил в репо автодеплой. Выбери один вариант:

### Вариант A — GitHub Pages (проще всего, ничего нового заводить не надо) ⭐
1. В репозитории: **Settings → Pages → Build and deployment → Source: `GitHub Actions`**.
   (workflow `.github/workflows/deploy-pages.yml` уже в репо — он сам соберёт `index.html`.)
2. Если деплой идёт с этой ветки, а не с `main`: **Settings → Environments → `github-pages`
   → Deployment branches** → добавь ветку `claude/correctness-check-0q39av`
   (либо просто смёрж ветку в `main`).
3. Через ~1–2 минуты сайт будет тут:
   **https://marino4ka-witch.github.io/casario/**
4. В Supabase → **Authentication → URL Configuration**:
   - **Site URL**: `https://marino4ka-witch.github.io/casario/`
   - **Redirect URLs** → добавь: `https://marino4ka-witch.github.io/casario/`

### Вариант B — Netlify (свой домен, чуть удобнее для маркетинга)
1. Netlify → **Add new site → Import from GitHub** → выбери `casario`.
2. Настройки сборки Netlify возьмёт из `netlify.toml` (уже в репо) — жать ничего не надо.
3. Получишь адрес вида `https://<имя>.netlify.app` (можно потом свой домен).
4. В Supabase → **Authentication → URL Configuration** пропиши этот адрес
   в **Site URL** и **Redirect URLs**.

> Важно: без шага «Redirect URLs» письмо со ссылкой придёт, но по клику Supabase
> не пустит обратно в приложение. Это одна строка в настройках — и вход заработает.

### Письма (email) для входа
Supabase на бесплатном тарифе шлёт письма со своего адреса с лимитом (~3–4/час) —
для теста хватает. Для продакшена подключи свой **SMTP**
(Authentication → Emails → SMTP): подойдёт Resend/Brevo/SendGrid — скажи, помогу настроить.

## Шаг 3. Платежи — Telegram Stars ⭐ + Stripe 💳 (код готов)

Единый платёжный слой уже в приложении (`window.PAY`): внутри Telegram платит
через **Stars**, на обычном сайте — через **Stripe** (карта). Без ключей всё
работает как демо и ничего не ломается. Серверная часть — две готовые
Supabase Edge Functions в `supabase/functions/`. Осталось подключить твои ключи.

**Как определяется способ оплаты:** приложение открыто внутри Telegram → Stars;
открыто как сайт → Stripe. Кнопки оплаты (подбор $10, PRO $20/мес, поднятие $2/$5)
уже ведут в этот слой.

### 3.1 Telegram Stars ⭐
1. У **@BotFather** создай бота → пришли мне (или впиши в секреты) его **token**.
2. Включи боту приём Stars (BotFather → бот → *Payments* → Telegram Stars).
3. Задай секреты и задеплой функцию:
   ```bash
   supabase link --project-ref vlhexxuzhdfiklcymawj
   supabase secrets set TELEGRAM_BOT_TOKEN=123456:ABC...
   supabase secrets set STARS_PER_USD=60          # сколько ⭐ за $1 (подстрой под курс)
   supabase functions deploy create-invoice --no-verify-jwt
   ```
4. В @BotFather пропиши Mini App / кнопку меню на адрес сайта из Шага 2 —
   и приложение откроется внутри Telegram с оплатой Stars.

### 3.2 Stripe 💳 (карта на сайте)
1. Заведи аккаунт на https://stripe.com (для реальных денег нужна верификация бизнеса;
   для теста сразу есть `sk_test_...`).
2. Задай секрет и задеплой функцию:
   ```bash
   supabase secrets set STRIPE_SECRET_KEY=sk_test_...   # позже sk_live_...
   supabase functions deploy create-checkout --no-verify-jwt
   ```
3. После оплаты Stripe вернёт пользователя на сайт с `?paid=<товар>` — доступ откроется.

> Пришли мне **token бота** и (когда будешь готова) **Stripe secret key** —
> и я всё задеплою и проверю. Ключи-секреты я **не коммичу** в репозиторий.

> Безопасность на будущее: для продакшена стоит добавить проверку Telegram `initData`
> (HMAC по токену бота) и Stripe-webhook, чтобы доступ выдавался по подтверждению
> с сервера, а не только по возврату на клиент. Скажи — добавлю.

## Что делаю я (весь код)
- Вход по email (magic link) + анонимный режим для «просто посмотреть».
- Облачные: профиль, объявления (общие, с модерацией), чат по странам (realtime), заявки на подбор.
- Честный **поиск-консьерж**: бриф → в базу → ты/агент с AI присылаешь 10 вариантов.
- Мягкий фолбэк: без ключей всё работает как сейчас (localStorage) — ничего не ломается.
- Платежи (Stars/Stripe) и деплой — по выбору из Шага 2.

## Производительность (первый экран)
- Файл — один HTML: **~1.25 МБ на диске**, но по сети хост отдаёт его сжатым:
  **~580 КБ gzip** (Netlify/большинство хостингов включают gzip/brotli автоматически —
  brotli даёт ещё меньше, ~450–480 КБ). Для контентного приложения это нормально.
- Тяжёлые части: фото стран (~500 КБ) и тексты гидов + карта (~750 КБ).
  Фото стран и гиды **рендерятся по требованию** (только когда открываешь страну),
  а не все сразу — первый экран лёгкий.
- Картинки помечены `decoding="async"` / `loading="lazy"`, чтобы не подвешивать прокрутку.
- **Хочешь ещё быстрее на реальном сайте?** Можно вынести фото/гиды в отдельные
  файлы и кешировать их браузером (сейчас всё в одном файле — так работает превью
  в claude.ai, где внешние запросы запрещены). На Netlify это безопасно и ускорит
  повторные заходы — скажи, и я разнесу ассеты для деплой-версии.
